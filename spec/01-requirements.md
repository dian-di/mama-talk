# 01 需求与约束

## 1. 问题定义

库内为英语学习资料（英文单词、常用短语、常用句子），每条有独立的中文翻译字段。用户以中文做非精确检索，期望命中对应英文条目；未精确命中时后台打标，提示人工补齐。

**性质判定：这是中文单语匹配，不是跨语言检索。** query 是中文，被检索字段也是中文；英文原文是返回内容，不参与相似度计算（唯一例外是 L2 reranker 的 doc 侧拼接中英双字段）。因此不需要跨语言 embedding 对齐，也不需要在线翻译主路径。

## 2. 验收 case

| 中文 query | 期望英文 | 类别 | 说明 |
|---|---|---|---|
| 狗 | `dog` | 词典直译 | 精确匹配 |
| 你在干什么 | `what are you doing` | 共识译法 | 基础 case |
| 干嘛呢 | `what are you doing` | 口语变体 | **必须在主路径命中**，不得折叠为相关推荐 |
| 时光如梭 | `time flies` | 意译 | 中英字面零交集 |
| 你自找的 | `you asked for it` | 意译 | 固定搭配 |
| 不要算我 | `count me out` | 最小对立对 A | 中文共享「算我」，语义相反 |
| 算我一个 | `count me in` | 最小对立对 B | 同上 |
| 我明白了 | `I see` | 意译 | 中英字面零交集 |
| 我不干了 | `I quit` | 口语固定搭配 | 别名空间发散 |

**最小对立对硬性验收**：query `算我一个` 时，`count me in` 必须判精确对应，`count me out` 必须判**不相关**，不得判为联想相关。

## 3. 数据构成

| 类型 | 条数 | 中文翻译性质 | 来源 | 别名策略 |
|---|---|---|---|---|
| 单词 | 10,000 | 大多是直译 | 权威词典，带义项与词性 | 义项直接导入，**不生成** |
| 常用短语 | 3,000 | 意译 + 直译混合，英语教育圈共识译法 | 教材 / 词表 | 8–12 个/条 |
| 常用句子 | 2,000 | 同上 | 教材 / 词表 | 8–12 个/条 |
| **合计** | **15,000** | 全部有独立中文翻译字段 | | 约 6–9 万行别名 |

译法性质按类型分层：单词以词典直译为主；意译固定搭配集中在短语与句子。这一差异决定分型策略，但不用于在线路由（见 `02-architecture.md`）。

## 4. 已确认约束

| 项 | 值 | 对方案的影响 |
|---|---|---|
| 数据规模 | ≤ 2 万（实际 15,000） | PG 单库；精确暴力余弦；不建 HNSW；不引入中间件 |
| 中文翻译字段 | 已存在 | 主路径查中文字段，无需预构建跨语言对齐 |
| 近义扩展 | 用户接受 `puppy` / `canine` / `hot dog` | 召回可宽进，不设硬阈值 |
| 口语变体与联想扩展 | **必须在主路径** | 不能折叠为「相关推荐」 |
| 描述式 query | **不在范围内**（如「形容很累的那个词」） | verifier 用 reranker，不必上 LLM verifier；L0 prompt 可结构化收窄 |
| L3 同步延迟 | 允许 | S3 可同步调用 LLM |
| 人工工作流 | 后台反复核验并修正翻译结果 | 别名需 `source` + `verified`；LLM 回填不得覆盖人工核验结果 |

## 5. 非目标

- 描述式 / 元查询（「形容很累的那个词」）。
- 英文 query 检索；本期只处理中文 query。
- 自动生成中文翻译字段；该字段已存在且由人工维护。
- 任何形式的在线翻译作为主路径。
- 多租户、高并发、水平扩展架构。

## 6. 术语

| 术语 | 定义 |
|---|---|
| 精确对应 | query 与条目语义等价，是期望返回的答案 |
| 并列精确对应 | 显式登记且已核验的一对多关系（词典多义项、多个共识译法），全部返回、不打标 |
| 联想相关 | 近义但非对应（puppy / canine），主路径返回并打标 |
| 不相关 | 无语义对应，打标 |
| 动态准入 | S0 短路只看「是否精确命中 + 歧义检测是否通过」，不看条目类型 |
| 最小对立对 | 中文字符串高相似、语义相反的一对条目（`count me in` / `count me out`） |
| `r` | 落到 S3 的 query 占比，只能由线上 query 日志统计 |

## 7. 打标语义

「索引不到」的定义不是「没有返回结果」，而是**没有精确对应」。因此：

- 有精确对应 → 正常返回，不打标。
- 只有联想相关 → 主路径返回，但**触发打标**：说明库里缺精确对应项。
- 完全不相关 → 打标。
- 低置信命中 → 打标并标记 `low_confidence`。

这一设计能抓到「看似有结果、其实没对齐」的隐性缺口，比「没结果才打标」更准。
