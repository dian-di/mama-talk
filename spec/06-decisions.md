# 06 决策记录与反例检验

ADR 风格记录。每条包含：当时的判断、推翻它的反例、修正后的结论。**改架构前先读这份**，避免把已排除的方案重新讨论一遍。

## ADR-01 从跨语言检索降为中文单语匹配

- 初始判断：需要离线预构建中文别名，用跨语言 embedding 对齐中英。
- 反例：库里**已有中文翻译字段**，query 与被检索字段都是中文。
- 结论：跨语言问题不存在，L1 天然在库里，无需预构建对齐。

## ADR-02 用户接受近义混淆，但纯向量仍不成立

- 初始判断：`狗` 召回 puppy / canine / hot dog 是缺陷。
- 用户裁决：可接受。
- 新反例：ANN 永远返回 top-k，**没有「未命中」状态**，与「索引不到则打标」结构性冲突；且词级与句级相似度分数不在同一量级，全局阈值会系统性误判。
- 结论：接受的模糊性消解的是「要不要分层」，不是「要不要判定」。需要独立的命中判定机制。

## ADR-03 人工修正的可预测性优先

- 反例：人工修正中文翻译的一个字，embedding 漂移多少、是否改变其他 query 的排序，无法局部推理。
- 结论：需求侧存在「后台反复核验并修正翻译」的闭环，确定性匹配比多召回几个近义词更重要；向量不能独占判定。

## ADR-04 判定与扩展分离被否决

- 判断：主路确定性检索独占判定，向量扩展折叠为「相关推荐」。
- 用户裁决：**口语变体（`干嘛呢`）和联想扩展必须在主路径**。
- 结论：改为三段式——L0 归一化 / L1 宽召回 / L2 验证判定。

## ADR-05 判定权从相似度分数转移给 verifier

- 反例：只要「是否命中」由相似度阈值决定，宽召回与明确打标就无法共存。
- 结论：**召回宽进、判定收口**。L1 不设硬阈值（阈值只截断候选数），L2 reranker 输出三分类与置信度，命中与否只看 L2。这是「结构性冲突」的正解，不是调参。

## ADR-06 联想扩展本身触发打标

- 反例：若联想扩展也算命中，打标几乎变成空集；用户搜「狗」只召回 puppy 其实说明库里缺精确项。
- 结论：打标定义从「没有返回结果」改为**「没有精确对应」**。能抓到「看似有结果、其实没对齐」的隐性缺口。

## ADR-07 缓存救不了长尾，在线成本转离线

- 反例：缓存优化掉的恰是不需要优化的部分——直译词高频集中，口语变体措辞发散、命中率最低。
- 结论：离线批量生成变体表（在线 query 直接命中），S3 结果回填 S2。LLM 在线调用率从 100% 压到长尾。
- 注意与 ADR-01 的区别：预构建的不是「中文↔英文对齐」（库里已有），而是「中文表达↔标准中文表达」，不参与判定，不影响确定性。

## ADR-08 三类语料必须分型，但依据是译法性质

- 反例：把 15,000 条当同质数据，会强迫在 1 字单词与 30 字句子之间取折中阈值；`pg_trgm` 对单字中文靠 padding 才能凑出 trigram，区分度差。
- 结论：单词走 B-tree 精确 + 词典义项；短语走 trigram + 向量；句子以向量为主。分型用于索引与离线生成，**不用于在线路由**（见 ADR-11）。

## ADR-09 意译共识译法带来「高相似误判」

- 反例：`不要算我`(count me out) 与 `算我一个`(count me in) 共享「算我」，中文 trigram 相似度高但**语义相反**。这是英语教材刻意成对教的最小对立对。
- 边界：用户接受的 puppy / canine 是**近义扩展**；反义混淆是**错误答案**，在学习资料里会被记住，不能据此外推接受。
- 结论：S0 短路从 `similarity ≥ 阈值` 改为**精确相等**；reranker 的 doc 侧拼接「中文翻译 ‖ English」；golden set 增最小对立对专项组。
- 附带反向验证：`我明白了` / `I see` 中英字面零交集，证明「主路径查中文字段」正确，任何在线翻译主路径会全军覆没。

## ADR-10 权威词典让单词类完全确定性化

- 输入：10,000 单词大多是直译，来自权威词典，带义项与词性。
- 结论：译义直接导入、不调用 LLM；离线生成范围从 15,000 收窄到 5,000 条，**调用量降约 67%**；单词类在线零 LLM / 零向量 / 零 reranker。
- 新暴露的问题：**一词多义**是系统性多对多（明白 → see / understand / realize；run → 跑 / 经营 / 运转）。若按「联想相关 → 打标」直接套，正常词典关系会淹没打标队列。
- 结论：显式登记且已核验的多对多 = 并列精确对应，全部返回、**不打标**；未登记或来源冲突 = 译法歧义，禁止短路并打标。

## ADR-11 动态准入，不按类型硬分流

- 反例：用户说单词「大多是直译」，意味着存在非直译单词；短语与句子里也有直译条目。按 `corpus_type` 写死分支会两侧漏判。
- 结论：S0 准入只看「是否精确命中 + 歧义检测是否通过」，与条目类型无关。这是对 ADR-08 分型的必要约束。

## ADR-12 存储与组件收敛

- 反例：15,000 条规模下，Elasticsearch、独立向量库、进程内 numpy 矩阵都解决的是「规模 + 语义鸿沟」，而这两个问题都不存在；ANN 索引还会引入近似漏召回。
- 结论：PG 单库 + pgvector 精确暴力扫描（不建 HNSW）+ pg_trgm + B-tree；模型本地常驻；无任何中间件。

## 落盘时修正的两处不一致

讨论是逐轮演进的，两处前后表述冲突，spec 正文已统一：

1. **歧义 vs 并列精确对应**：早期规则为「同一中文别名指向 ≥2 条英文 → 禁止短路并打标」，后期规则为「并列精确对应 → 全部返回不打标」。二者直接冲突。修正为按数据状态区分：全部 `verified = true` 且 `relation_type = parallel_exact` 视为并列精确对应；存在未核验或来源冲突才判译法歧义。见 `03-data-model.md` 第 4 节。
2. **query 类型标签命名**：早期「直译词 / 直译句 / 口语变体」中的「直译句」与「句子含大量意译」冲突。重命名为 `word_query` / `phrase_sentence_query` / `variant_query`。见 `05-evaluation.md` 第 2 节。

另有一处属正常演进而非冲突：S0 短路条件从 `similarity ≥ 0.85` 收紧为精确相等（ADR-09），正文统一采用后者。
