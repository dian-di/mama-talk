# 05 评测方案

## 1. golden set 构成（约 300 条）

| 组 | 条数 | 构成 | 验证目标 |
|---|---|---|---|
| 精确对应 | 150 | 三类 query 各 50 | 召回准确率、S0 短路覆盖率 |
| ├ 单词类 | 50 | 词典直译，含多义项词条 | B-tree 精确匹配、并列精确对应 |
| ├ 短语 / 句子类 | 50 | **直译倾向 25 + 意译倾向 25** | 覆盖译法性质差异；`pg_trgm` 与向量的分档阈值 |
| └ 口语变体 | 50 | 按 S1 可覆盖 / S2 变体表已覆盖 / 长尾需 S3 分层，各约 15–20 | S1 规则边界、S2 覆盖率 |
| 联想相关 | 40 | 如搜「小狗」期望 `dog` 精确、`puppy` 联想 | 「返回 + 打标」是否触发 |
| 负样本 | 60 | 库里确实没有对应英文资料；其中 **20 条语义高度相近但库里没有** | 打标触发率、误报率、verifier 幻觉对齐 |
| 最小对立对 | 25 | `算我一个` / `不要算我` 等成对条目 | 反义项必须判**不相关**，不得判联想相关 |
| 并列精确对应 | 25 | 「明白 → see / understand / realize」等词典多对多 | 全部返回且**不打标** |
| **合计** | **300** | | |

**每类 50 条是下限**：单组准确率估计的置信区间约 ±10%，再少就分不清 85% 与 95% 的差别，调阈值会变成对着噪声调参。

**负样本不可省略**：若评测集全是「应该命中」的样本，一个「永远返回 top-1 且从不打标」的系统能拿满分——召回率 100%，而打标逻辑完全没被验证。打标是本需求的核心。

## 2. query 类型标签

| 标签 | 含义 | 对应语料 |
|---|---|---|
| `word_query` | 单词 / 直译查询 | 10,000 单词 |
| `phrase_sentence_query` | 短语与句子，共识译法（意译 + 直译混合） | 3,000 短语 + 2,000 句子 |
| `variant_query` | 口语表达变体 | 跨类型 |

> 命名演进：讨论早期曾称「直译词 / 直译句 / 口语变体」。确认句子含大量意译后，「直译句」不再准确，故改为上表标签。标签用于 golden set 分层与日志统计，**不用于在线路由**。

## 3. 指标定义

| 指标 | 计算 | 目标 |
|---|---|---|
| 精确对应召回率 | 按各组分别统计，不合并 | 分层观察，不用单一全局数 |
| 打标准确率 | 负样本触发打标 / 负样本总数 | 高 |
| 打标误报率 | 精确对应组被误打标 / 精确对应总数 | 低 |
| 最小对立对通过率 | 反义项被判不相关的比例 | **100%** |
| 并列精确对应不打标率 | 该组未触发打标的比例 | **100%** |
| S0 短路覆盖率 | `s_level_hit = S0` 的 query 占比 | 越高越好，主流量应保持毫秒级 |
| `r` | `s_level_hit = S3` 的 query 占比 | 由线上日志统计，非 golden set 指标 |

指标必须**分组统计**。单词与句子的相似度分数不在同一量级，合并成一个全局准确率会掩盖其中一类的系统性失败。

## 4. 阈值调参

待定阈值（spec 不预设数值）：

- `pg_trgm` 宽召回阶段的候选截断数 K（仅截断候选，**不用于判定命中**）
- reranker 三分类的置信度边界
- S1 规则归一化的适用边界（叠词、助词、同义替换表）
- 单词 / 短语 / 句子三档的 `pg_trgm` 相似度分档

调参方式：以 golden set 分组指标为目标函数，分档独立调，不设全局单一阈值。每格样本量决定调参粒度，不要在 20 条样本上追求小数点差异。

## 5. 回归基线

以下任一变更后必须全量重跑 golden set：

- 人工批量修正中文翻译
- 调整 L0 归一化 prompt 或 S1 规则表
- 更换 embedding 或 reranker 模型
- 变体表批量回填
- 阈值调整

回归的价值在于：人工改了什么，评测集立刻能告诉系统是变好还是变坏，避免「修好一条、弄坏一批」。这是「可预测性优先」约束在评测侧的落实。

## 6. 上线后的数据闭环

1. 全量记录 `query_log`（含 `query_type`、`s_level_hit`、`verdict`、`top_candidates`）。
2. 统计真实 query 形态分布与 `r`，用数据收敛「不确认用户会如何索引句子」这一不确定性。
3. 按 `tag_queue.hit_count` 排序投入人工；高频 miss 优先固化进变体表。
4. 高频 query 形态固化为别名后，LLM 在线调用自然收敛到长尾。
